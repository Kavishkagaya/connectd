# openConnect — Decisions

- Built entirely on Cloudflare Durable Objects. No separate server/DB service.
- One Durable Object per connection (not per connector/provider).
- DO ID derived deterministically: `idFromName(team:provider:tenant)` — no router needed to look up a single connection.
- D1 as the global index for listing/querying connections (DOs aren't bulk-queryable).
- DO owns the full OAuth lifecycle: authorize, token exchange, refresh, revoke.
- Token refresh via DO `alarm()` (proactive, before expiry) — not cron/polling.
- Single-threaded DO execution relied on to avoid concurrent-refresh races — no manual locking.
- Per-provider OAuth config (URLs, scope format, PKCE support, refresh/revoke quirks) as data/config, not hardcoded per provider.
- Client secrets encrypted at rest (AES-GCM, key from Worker secret) before storing in DO/D1.
- Start with 2-3 known providers first; generic "any provider" support deferred.
- Attempt OAuth Dynamic Client Registration (RFC 7591) opportunistically for Custom OAuth providers that support it; manual client_id/secret entry as fallback. Deferred — not day one.
- Connector config (client_id/secret, endpoints) lives in one Team DO per team, keyed `idFromName(team)` — holds every provider's connector config for that team. Connection DOs (`team:provider:tenant`) call it for secrets at authorize/refresh time. Not Cloudflare Secrets Store (wrong shape: that's for a small static set of account-level secrets, not high-cardinality per-tenant ones). Coarser than per-connection sharding, acceptable because secret reads are cold-path (authorize/refresh only, never on a plain getToken against a valid grant).
- Single master AES-GCM key (Wrangler/Workers secret) encrypts all connector/connection secrets at rest. Ciphertext tagged with a key-version byte so the key can rotate later without a full re-encrypt migration.
- API secret keys (team → Worker) are hashed (SHA-256), never encrypted/stored raw — same pattern as Stripe/GitHub API keys.
- Worker→DO calls and DO→provider calls need no extra crypto: the former never leaves Cloudflare's runtime (no public DO endpoint to attack), the latter is plain HTTPS. Only data at rest needs app-level encryption.
- API auth (server-to-server, customer backend → openConnect): per-team secret key (`sk_...` style), hashed in D1.
- Two separate route groups on the Manager Worker, two separate auth middlewares: `/management/*` (create/delete connector, create/revoke API keys, list connections) verifies Clerk session JWT via `@clerk/backend` (networkless, Workers-native); `/v1/*` (oauth start/callback, get token, revoke) verifies the team API secret key. Dashboard only ever calls `/management/*`.
- Dashboard/human auth: Clerk. Clerk Organizations used directly as the `team` primitive — no custom team model.
- v1 providers: GitHub, Slack, Google.
- v1 ships a dashboard (Clerk-authed): create/manage/delete connectors, create/revoke API tokens, view/manage connections. Not API-only.
- No webhooks in v1 — customer apps poll connection status. Add webhooks later if needed.
- Dashboard is a pure SPA — Vite + TanStack Router (client-only, no SSR/Start) — since it's just a Clerk-authed frontend calling the Manager Worker's API, not running its own backend logic. Deployed as static assets on Cloudflare Workers Static Assets.
- Dashboard calls the Manager Worker's public API (dogfooding) via fetch, not direct DO/D1 bindings — even though it's served by the same Worker.
- Single Worker deployment, not two: the Manager Worker serves the dashboard's built static assets (Cloudflare Static Assets binding) alongside its own `/v1/*` and `/management/*` routes. Separate source packages, one deploy target — no second Worker, no CORS.
- Monorepo: Bun workspaces, Biome/Ultracite for lint/format. `apps/api` (Manager Worker + DOs + D1, serves dashboard static assets too), `apps/dashboard` (Vite + TanStack Router SPA, builds to static files), `packages/shared` (provider configs, types, crypto helper).
